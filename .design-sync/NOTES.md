Target: the design-system artifact https://claude.ai/artifact/JRrSbSw7WMvvxRr57oBmWD ("Log-Log Legends
Kit"). Refresh it with `refresh-kit.sh` and an Artifact publish (see "Refreshing the kit" at the end).
The Claude Design project in config.json is retired. The artifact at
claude.ai/artifact/2DfxHtPMWbJSRnDk19Hxf8 is a separate, tokens-only system.

## How the build works

- The repo has no package build, so `.design-sync/pkg/` is a small wrapper package the converter
  reads: `entry.ts` (re-exports `src/kit` plus `setup/CorridorRoot`), `tsconfig.json` (the site's,
  plus path swaps) and `build.sh` (`cfg.buildCmd`). Run `build.sh` before every converter run.
- `build.sh` writes `gen/site.css` (type.css + corridor.css + post.css, `@font-face` stripped;
  the font ships through `extraFonts`), `gen/docs/<Name>.md` (src/kit/README.md split per `###`
  section, `##` heading = group) and `types/` (tsc declarations). All gitignored.
- Converter command: `node .ds-sync/package-build.mjs --config .design-sync/config.json
  --node-modules ./node_modules --entry .design-sync/pkg/entry.ts --out ./ds-bundle`.
- Shims, each needed for the bundle to load or draw:
  - `env.ts`: `src/scripts/site.js` reads `process.env.NEXT_PUBLIC_*`, which esbuild leaves as a
    runtime read; without the shim the IIFE throws `process is not defined`.
  - `vendor-shim.ts` replaces `@/scripts/runtime/vendor.js`: the site loads ECharts and D3 by
    `<script>` from `/assets/vendor/`, which doesn't exist in Claude Design. The bundle carries both
    (~1.3 MB). The repo is `"type": "module"`, so the UMD files are side-effect imports that set
    `globalThis.echarts` / `globalThis.d3`; a default import fails.
  - `next-error-stub.tsx` replaces `next/error`: `src/lib/island.tsx` imports it, and the kit only
    needs that file's `report()`.
- `CorridorRoot` (cfg.provider) puts `corridor` on `<body>` and renders `<main class="shell">`.
  `useTokens` reads tokens from `document.body`, so a wrapper div is not enough; tables are styled
  only under `.corridor main table`.
- The component's directory sets its group (`setup/` → Setup); doc `category` only applies when the
  path gives `general`.
- Playwright: the repo's node_modules has none. `.ds-sync` installs `playwright@1.62.1`, which pins
  chromium-headless-shell 1234, the build cached in ~/Library/Caches/ms-playwright. The repo pins
  1.63.0 (build 1243), which isn't cached.

## Re-sync risks

- `vendor-shim.ts` names `echarts-5.5.1.min.js` and `d3-7.9.0.min.js`. If the kit bumps a vendored
  version, `loadVendor` rejects the new file name and EChart / explorable NetworkView cards go blank.
- `next-error-stub.tsx` mirrors `catchError`'s shape; a new `next/error` import in the kit's closure
  that needs more than `catchError` will fail to build.
- The `NetworkView` preview's inlined graphs go stale if `graphs.json` is regenerated (harmless for
  rendering, but the cards stop matching the kit page).
- `split-readme.mjs` relies on the README's `## Group` / `### Name(` layout; a reformatted README
  drops docs (`[DOCS_UNMAPPED]`).
- `build.sh` uses `|| true` on tsc because the site's code has type errors under declaration emit
  settings; it checks only that `entry.d.ts` exists. A missing component `.d.ts` shows up as
  `[DTS]` warnings in the build log.
- `env.ts` defines a global `process = { env: {} }` in every design that loads the bundle. A library
  that sniffs `typeof process` to detect Node could take its Node path.
- Conventions header: `p.sub` is styled only as a direct child of `.card`; check any class the
  header names against the selector it actually has, not just its presence in the CSS.

## Post and site components (added 6 Oct, second pass)

  instructions into `gen/guidelines/`; they ship under `guidelines/gen/`.

  fixes it to the viewport). FindingsStrip is `column` at 900x900 (Week 4's five rows overflow
  700px). Grid cells are about 520-670px, so Anatomy and HowTo squash to one word per line in a
  narrow parent; their previews sit in a 640px card, and the Card and PostSection previews stack
  instead of using Week 5's two-column `.w4-two` layout. QuestionCard's FigureBelow shows three of
  the five crossing rows to fit its cell.
- Context-only styling: BrandMark needs `div.topbar > div.shell` (its colours are `--bar-*`);
  HeroStat needs `section.hero.w4-hero > div.shell > div.w4-hero-text > div.w4-hero-stats`
  (`--w4-hero-*`); SkipLink sits off screen until focused, so its preview focuses it.

  `details.open` in a layout effect.
- PostHero's Week 5 figure is a static SVG precomputed with `fameLayout()` from fame.json (EChart
  would draw dark axes on the dark hero).
- Real data in previews: Week 5 `public/weeks/week05/data/*.json` (relations, communities, fame,

## Refreshing the kit (since 15 Oct 2026)

`.design-sync/refresh-kit.sh` runs the converter's build stage only (no upload) and stages what changed:

1. Run `.design-sync/refresh-kit.sh BrandMark,PostTopbar` (the list is optional: those components are
   photographed to `ds-bundle/_screenshots/review/` so you can look before publishing). It restores the converter
   into `.ds-sync/` from `~/.cache/log-log-ds-sync` when missing, clones `node_modules` from another worktree with
   `cp -cR` when missing, runs `pkg/build.sh` and `package-build.mjs` into `ds-bundle/`, then `stage-kit.mjs`.
2. `stage-kit.mjs` turns `ds-bundle/` into the kit's files with `kit-layout.mjs`, compares each file's sha256
   with `kit-published.json` (what was last published), and copies only changed or new files to
   `ds-stage/project/`.
3. Read the kit's `project/design-system.json` again, copy it to `ds-stage/project/`, set only `lastChange`
   (`by` Gyula, `via` Claude Code, `at` now, a note) and keep every other key.
4. Publish in one Artifact call: `url` the kit, `root` = absolute path of `ds-stage`, `file_path` = the index,
   `files` = every staged path mapped to itself. `.d.ts` files need `{"from": path, "contentType": "text/plain"}`
   (the artifact serves no `.ts`). At most 255 paths a call; if more, send the index in the last call only.
5. After the publish succeeds, run `node .design-sync/stage-kit.mjs --record` and commit `kit-published.json`.

The kit's layout since the 15 Oct "Finish the migration" clean-up is the Design System type's own
(`kit-layout.mjs` header has the mapping):

- `components/bundle.js` is `_ds_bundle.js` as built. `components/lib/react.js` and `react-dom.js` carry React
  19.3.0 (react.js sets `ReactDOM` too; react-dom.js is a stub), named in the index's `libraries`.
- `components/bundle.css` is KaTeX's `@font-face` rules from `fonts/fonts.css` plus `_ds_bundle.css`, minus what
  `tokens.json` declares outside `.corridor`: the `--font-sans/display/mono` stacks and Cold Read's repeated
  `:root` colours. `tokens.css` (loaded first) is their only source, so an edit on the kit page shows.
- `components/<Name>/preview.html` inlines `_preview/<Name>.js` and the old card's mount script; the page
  preloads tokens.css, bundle.css, the libraries and bundle.js. Line 1 is the `@dsCard` marker with the
  converter's group; `single` cards take their viewport from `config.json` overrides.
- `components/<Name>/README.md` is `<Name>.prompt.md`, `<Name>.d.ts` as built, and `components/index.d.ts`
  joins every `.d.ts`.
- Edited in the kit only, never staged: `README.md`, `tokens.json`, `tokens.css` (the page regenerates it on
  save), `components/Cover/preview.html` and the guidelines.
- `archived/` holds the migrated layout (old cards, `.jsx` stubs, `_preview/`, `_ds_bundle.css`, `styles.css`,
  `fonts/fonts.css`, `_ds_manifest.json`); delete it only when Gyula asks.

Colours in `tokens.json` are the corridor's, but components read them from `.corridor` on `<body>` (set by
`CorridorRoot`), so a colour edited on the kit page does not reach the previews; type families do.

Before publishing changed previews, render them as the page does: serve `ds-stage/project` (with `tokens.css`
and `fonts/` copied in) and load each preview after `tokens.css`, `components/bundle.css`, the libraries and
`components/bundle.js`. On 15 Oct all 96 (with the Cover) rendered with no console errors.

The converter (`.ds-sync/`: package-build.mjs, package-capture.mjs, lib/, its own node_modules with esbuild,
ts-morph and playwright 1.62.1) is not in the repo and Claude Design no longer hands it out. The copy in
`~/.cache/log-log-ds-sync` came from the `design-sync-6139d9` worktree on 15 Oct; keep it. `kit-published.json`
was rewritten after the clean-up from the 290 files `kit-layout.mjs` produced, each byte-identical to what was
published.

`env.ts` also points root-relative portrait images (`/02805_social_graphs/play/cold-read/portraits/...`, as
