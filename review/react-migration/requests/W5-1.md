# W5-1 requests

## 1. HoverTipHost: mark its element as React's and keep the server's attribute order

**Status:** open. W5-1 works around it with a shim, `src/features/week05/frame/OwnedHost.tsx`
(`// shim: W5-1`), passed to HoverTipHost as `as`.

**File:** `src/kit/HoverTipHost.tsx` (K1b)

**Why.** Spec step 3 of W5-1 (and W5-2, W5-3 after it): the Week 5 hover-tip compat sweep
(`src/features/week05/frame/hovertips-compat.js`) runs tips.js `hoverTips()` on every `[id^="chart-"]` host
that is not `isOwned`, and a converted host is owned through `useOwnedRef` at the commit. HoverTipHost puts its
own ref on its element (`{ ...attrs, ref: host, ... }`), so a caller cannot pass `useOwnedRef()`; without it the
sweep would give a React host a second tip div and a second set of listeners. HoverTipHost also writes
`className` after the other props, so a host React creates afresh after hydration comes out as
`aria-label, id, role, class`, where main keeps the server's `aria-label, class, id, role`
(HOVERTIPS.md, chart-hero-fame). The shim reorders them; runtime parity sorts attributes, so only a raw
`outerHTML` comparison (W5-1's `heroHtml` evaluate step) sees the order.

**Patch.**

```diff
--- a/src/kit/HoverTipHost.tsx
+++ b/src/kit/HoverTipHost.tsx
@@
 import TipBox, { type Tip } from "./TipBox";
+import { useOwnedRef } from "@/lib/useOwnedRef";
@@
 export default function HoverTipHost({ as = "div", className, tip: initial = "first", redraws, children, ...attrs }: HostProps) {
   const host = useRef<HTMLElement | null>(null);
+  const own = useOwnedRef();
+  // Marked as React's at the commit, so a page's legacy hover-tip sweep skips it.
+  const ref = useCallback((el: HTMLElement | null) => {
+    own(el);
+    host.current = el;
+  }, [own]);
@@
+  // className where the server markup has it: before id and role.
+  const { "aria-label": label, ...rest } = attrs;
   return createElement(
     as,
-    { ...attrs, ref: host, className: withClass(className, "kit-tip-host"), onPointerOver, onPointerMove, onPointerOut, onPointerLeave: cool },
+    { "aria-label": label, className: withClass(className, "kit-tip-host"), ...rest, ref, onPointerOver, onPointerMove, onPointerOut, onPointerLeave: cool },
     [spot === "first" ? box : null, content, spot === "last" ? box : null],
   );
```

(`useCallback` joins the react import.) Once it lands, W5-1's Frame.tsx drops `as={OWNED}` and OwnedHost is used
only for the hero's server host, or is replaced by a plain div with `ref={useOwnedRef()}`.

## 2. HoverTipHost: pointer handlers read a stale hot mark

**Status:** open. W5-1 works around it in the same shim: `OwnedHost` runs every `onPointer*` handler inside
`flushSync`, so each event sees the state the one before it set.

**File:** `src/kit/HoverTipHost.tsx` (K1b)

**Why.** `onPointerMove` shows `hot.lines` from the closure of the last render. Pointer events are not flushed
synchronously, so when the pointer moves straight from one mark to the next, the `pointerover` on the new mark
sets the new lines and the `pointermove` right after it, handled before React renders, shows the old mark's
lines again. tips.js updates `hot` synchronously and shows the new mark. W5-1's scenario
(`scenarios/week05/W5-1.mjs`, "hover the hero's 150th dot" after the first) caught it: main's tip reads
"Karnak (character): 2,142 words, 4 incoming links", HoverTipHost's still reads "Abomination (character): …".
Any dense chart (the hero, the weird scatter in W5-3) shows it to readers.

**Patch.** Keep the hot mark in a ref the handlers read, and the state only for rendering:

```diff
--- a/src/kit/HoverTipHost.tsx
+++ b/src/kit/HoverTipHost.tsx
@@
   const [hot, setHot] = useState<{ el: Element; lines: string[] } | null>(null);
+  // What the handlers read: the mark hot after the last event, as tips.js's `hot`.
+  const hotNow = useRef<{ el: Element; lines: string[] } | null>(null);
+  const heat = (next: { el: Element; lines: string[] } | null) => {
+    hotNow.current = next;
+    setHot(next);
+  };
@@
   const cool = () => {
-    if (hot) cooled.add(hot.el);
-    setHot(null);
+    if (hotNow.current) cooled.add(hotNow.current.el);
+    heat(null);
     setTip((t) => (t ? null : t));
   };
   const onPointerOver = (e: PointerEvent) => {
     const el = (e.target as Element).closest?.("[data-tip]");
     if (!el || !host.current?.contains(el)) return;
     const lines = (el.getAttribute("data-tip") ?? "").split("\n");
-    if (el !== hot?.el) {
-      if (hot) cooled.add(hot.el);
-      setHot({ el, lines });
+    if (el !== hotNow.current?.el) {
+      if (hotNow.current) cooled.add(hotNow.current.el);
+      heat({ el, lines });
     }
     show(lines, e.clientX, e.clientY);
   };
   const onPointerMove = (e: PointerEvent) => {
-    if (hot) show(hot.lines, e.clientX, e.clientY);
+    if (hotNow.current) show(hotNow.current.lines, e.clientX, e.clientY);
   };
   const onPointerOut = (e: PointerEvent) => {
-    if (hot && !hot.el.contains(e.relatedTarget as Node | null)) cool();
+    if (hotNow.current && !hotNow.current.el.contains(e.relatedTarget as Node | null)) cool();
   };
```

The same applies to `redraws`: a redraw that drops the hot mark should also clear `hotNow.current`. Once this and
request 1 land, W5-1 drops OwnedHost from HoverTipHost's `as`.
