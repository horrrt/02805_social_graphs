# K2 requests

## 1. known-bugs.md and plan.json: record KB21, networkView redraws a chart already off the page

**Status:** pending. K2 keeps the behaviour, so nothing fails without this entry. The request only records the bug.

**Files:** `review/react-migration/known-bugs.md` (the KB list) and `review/react-migration/plan.json`
(`knownBugsPreserved`, which known-bugs.md copies verbatim).

**Why.** `networkView()` in `src/scripts/graph.js` keeps the chart it last drew in `chart` and redraws by
`chart.replaceWith(next)`. `fitted()` swaps in a new chart whenever the parent's width changes, and the first
measurement after a draw always changes it (640 by default against the column width). From then on, `chart` is
off the page and `replaceWith` does nothing. A move (movable) or a link hover (weights) therefore changes the
state and the legend but leaves the svg as it was. The next width change draws the new state. Repeated clicks
on one member keep moving it to the same group, because the visible node's handler still holds the group it
was drawn with. On main's kit page at 1440x900, clicking karate member 0 turns the legend into "Mr. Hi's club
(16 members), The officer's club (18 members)" while the node stays `gv-node g0`. `NetworkView`
(`src/kit/network/state.ts`, `live` and `orphan`) keeps this, and `scripts/parity/scenarios/kit/K2.mjs` checks
it.

**Patch.** Add this line after KB20 in both files (in plan.json, as a new string at the end of
`knownBugsPreserved`):

```
- KB21 Kit, Week 5, template: networkView redraws (a move, a weight-link hover) replace a chart that fitted() already swapped off the page, so after the first width measurement only the legend shows a move until the next resize; preserved by NetworkView's live/orphan model (src/kit/network/state.ts).
```
