# P1 requests

## 1. agentMeta.tsx: give the JSON-LD script an `// allow-html:` home

**File:** `src/components/agentMeta.tsx` (and `tests/react-rules.test.mjs`, which P1 owns now but a later batch
will own when this lands)

**Why:** `tests/react-rules.test.mjs` allows `dangerouslySetInnerHTML` only in files under `src/lib` whose first
line is `// allow-html: <reason>`. `JsonLd` in `src/components/agentMeta.tsx` renders its schema.org JSON into a
`<script type="application/ld+json">` that way, and every live page's layout uses it. P1 changes no file under
`src/`, so the test exempts that one file and pins the exact expression
(`dangerouslySetInnerHTML={{ __html: JSON.stringify(data).replace(/</g, "\\u003c") }}`) and the count of one. A
second use in that file, or the same use in any other file, still fails.

**Patch:** move the script element into `src/lib/JsonLdScript.tsx` and import it from `agentMeta.tsx`, then drop
`JSON_LD` from the test:

```tsx
// allow-html: JSON.stringify output with "<" escaped cannot close the script element.
export function JsonLdScript({ data }: { data: unknown }) {
  return <script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(data).replace(/</g, "\\u003c") }} />;
}
```

```diff
-  return (
-    <script
-      type="application/ld+json"
-      // JSON.stringify output is safe here once "<" is escaped.
-      dangerouslySetInnerHTML={{ __html: JSON.stringify(data).replace(/</g, "\\u003c") }}
-    />
-  );
+  return <JsonLdScript data={data} />;
```

The rendered `<script>` stays byte-identical, so `static.mjs` reports no difference. Any batch may apply it; the
orchestrator picks the wave.

## 2. Note: five week 3 ids exist only at runtime

Not a patch, a record. The widened id harvest in `tests/migration-docs.test.mjs` reads lookups from the variants
and `scripts/audit_week03.js`, and five ids they look up are created in the browser, never by the server page:
`globe-canvas-d3` (variants/d3.js), `globe-gl` (variants/globe.js), `globe-atlas` (variants/atlas.js),
`globe-canvas-deck` (variants/deck.js, `${canvasId}-deck`) and `style-earth` (week03-boot.js,
`style-${dimension.key}`). The spec has no `CLIENT_IDS` object for them yet, so the test lists them in
`RUNTIME_IDS` and asserts each stays absent from `out/weeks/week03/index.html`. When W3-2 (variant host
descriptors) and the style batch render these hosts, they move into `CLIENT_IDS` or island markup and leave
`RUNTIME_IDS`.
