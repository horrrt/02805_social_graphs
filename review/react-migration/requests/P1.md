# P1 requests

P1 departs from its spec in two places, both to stay green on main without changing `src/`. Neither weakens a
check the spec asks for on code that exists today. The orchestrator decides whether to keep them or amend the spec.

## 1. migration-docs.test.mjs: ids the week 3 code builds itself are not looked up in the built page

**Spec:** LOOKUPS gains every `getElementById("x")`, `$("x")`, … across corridor.js, week03-boot.js,
questions.js, echarts-views.js, variants/*.js and scripts/audit_week03.js, and each must be `id="x"` in
`out/weeks/week03/index.html`. Only template lookups (`${…}-x`) and CLIENT_IDS values are excluded.

**What fails without a change:** five ids are looked up but created at runtime by the same code, so the static
page never has them: `globe-gl` and `globe-atlas` (`host.id = "…"` in variants/globe.js and atlas.js),
`globe-canvas-d3` (variants/d3.js), `globe-canvas-deck` (`` host.id = `${canvasId}-deck` `` in variants/deck.js)
and `style-earth` (`` id="style-${dimension.key}" `` in week03-boot.js, read by audit_week03.js).

**What the test does:** an id assigned with `.id = "x"`, `` .id = `${…}-x` `` or `` id="x-${…}" `` in any scanned
file is excluded. The test now requires 87 ids on the page, against 58 before P1.

## 2. react-rules.test.mjs: a JSON-LD script may use dangerouslySetInnerHTML

**Spec:** `dangerouslySetInnerHTML` only in files under src/lib headed `// allow-html: <reason>` (R13 in P2c
narrows it to ChartTip).

**What fails without a change:** `src/components/agentMeta.tsx` (`JsonLd`, from #146) writes schema.org JSON into
`<script type="application/ld+json">` that way, on every live page.

**What the test does:** an occurrence inside a `<script type="application/ld+json"` element is not counted.
P2c's R13 should name JsonLd as the second allowed use, or JsonLd should move under src/lib with an
`// allow-html:` header.
